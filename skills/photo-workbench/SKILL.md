# 摄影工作台

把新照片、修图项目、已入库照片和需要本人判断的事情连成清楚的工作流。工作台应该直接看图、准确定位文件，并把用户反馈落实到照片和未来的执行方式中。

## 先了解使用者，再建界面

先读已有文件和规则。每轮只问 1–3 个会改变方案的问题；已有明确回答不重复问。

1. 留下照片为了什么：家庭记录、主题素材、单张作品、影集或交付？这些目标的先后顺序是什么？
2. 新照片从哪里来、放哪里？原片、成片、RAW／JPEG、视频分别保留什么？哪些目录或主题必须保留？
3. 谁筛选、谁修图、谁决定精选？用户怎样表达审美反馈？用户希望按什么顺序浏览和审核？
4. 实际存放在哪里，是否存在云端占位或离线存储？更新由会话通知、手动按钮还是明确授权的其他方式触发？不要默认建立定时器。
5. 哪些操作已获授权，哪些只作提案？以什么结果验收？

复述目标、输入、留存与删除边界、分类方式、用户与 Agent 的职责、更新触发和反馈去向。取得方案确认后才生成用户的 profile 和工作台。不要预填作者的家人、设备、主题、NAS、路径或审美。

## 构建与使用

先看 [最小运行方式](references/quickstart.md)。`scripts/bootstrap.py` 接受已经确认的 profile，在新目录创建一个可运行的本地工作台。随附的是可改造的起点，不是装上就自动看完所有照片的服务。

界面至少提供：
- 日常进度：输入、整理中、需修图、已入库和下一步；仅显示有实际记录的状态。
- 照片库：按已确认的主题／分类进入照片集，再看单张；直接显示预览、放大和准确文件定位。不同内容版本分列，同内容多位置关联，一图可属于多个主题。
- 唯一审核入口：图片／对照、具体问题、Agent 建议、用户选择和补充意见；保存后退出待判断，等执行与已完成分开；不把哈希、日志、技术阻塞塞进首屏。
- 反馈与经验：保留用户原话、具体落实、候选原则、采用、独立验证、生效和停用；后台证据按需查看。

实际导入由 Agent 按用户授权执行：盘点、真实看图、元数据核对、计划预检、复制读回验证、再处理源。不得把生成页面或索引当成完成筛选。不存在或离线明确显示，不能退到无关父目录冒充定位成功。不按单纯相似画面、文件名或匹配失败删除原片。

## 反馈必须被用起来

每次整理、选片或影集工作开始前，运行生成工作台中的 `python feedback.py context --root <工作台目录>`，完整读取返回的上下文文件。索引登记工具也执行这个入口并记录上下文版本。

具体意见先落实具体事项，留 source feedback ID 和证据回执。原话保留，不改写旧事件；去重只合并跟进，不删除来源。规则只抽象在多个照片／批次仍成立的主张，说明适用领域、边界、反例和已有规则冲突。单张姓名、单次日期、一个图的姿态不是 Golden Rule。

规则提议引用原反馈；用户采用后，至少在两个不同场景完成有证据的验证，且无未解决冲突，再生效。候选不能进入生效上下文。完整协议见 [反馈闭环](references/feedback-contract.md)。这是工作区内可复用记录，不是修改模型权重或永久记忆。

## 验收

保留旧记录，先在合成样本中测试保存、重开、冲突拒绝、撤回和未知暂存，再用真实照片检查分类、预览与文件定位。实际点击并检查桌面和窄屏；代码通过不等于用户满意。分别报告已实现、已测试、实际使用仍缺的证据。

公开分享只允许代码、通用文档和合成示例；不包含照片、家人资料、聊天、私人审美、数据库、真实路径或凭据。
